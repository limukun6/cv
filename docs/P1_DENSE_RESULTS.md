# Part 1 稠密设定结果（160 视角）

> 机器：AutoDL RTX 4080 SUPER 32 GB（sm_89，算力实测 94 TFLOPS，未被共享）
> 环境：Ubuntu 22.04 / Python 3.12 / torch 2.8.0+cu128 / nvcc 12.8.93
> 协议：**统一 160 个训练视角，30000 迭代**，参数全默认
> 采集时间：2026-11-04 20:21 – 22:56（约 2 小时 35 分）

---

## 为什么补这一轮

原文 Part 1 的输入条件是（L84）：

> "Scenario: Given a video of an object or scene captured with **dense views (sufficient data)**."

而 Part 2 才是（L110）：
> "**Sub-sample the data from Part 1** to create extremely sparse frames"

所以 **Part 1 必须是稠密设定**。之前那批主实验用的是 50 个视角
（占全量 16–25%），严格说落在"稀疏"一侧，不能代表 Part 1。

160 视角的选择依据：

| 依据 | 说明 |
|---|---|
| 落在学术界的稠密区间 | 3DGS 的 Mip-NeRF 360 场景是 121–311 张，100–300 是惯常范围 |
| 远高于 Part 2 的稀疏 | Part 2 是 9–19 帧（1/30、1/10），160 是它的 8–17 倍 |
| 显存可控 | VGGT 在 199 帧约 25 GB、Ω 约 21 GB，32 GB 卡可跑 |
| 三方法三场景完全可比 | 统一帧数，不出现混合设定 |

### 附带发现：COLMAP 的方差远大于前馈方法

```
COLMAP:     std 0.03 / 0.54 / 1.40 dB（三场景）
VGGT:       std 0.07 / 0.14 / 0.23 dB
VGGT-Ω:     std 0.03 / 0.04 / 0.07 dB
```

**COLMAP 的均值最高，但方差最大**（waymo 上单次能差 2 dB）。
前馈方法的初始化更"确定"——同一种子基本复现，换种子只差 0.1 dB 量级。

这在实践上很有意义：**要可复现、要稳定，前馈方法更好；要最好的一次结果，COLMAP 更高。**
报告里应当同时给出均值和方差，不能只报单次最优。

## 3. 关键发现

### ① COLMAP 的优势随视角增加而**扩大**，而且原因是它的位姿精度暴涨

先看渲染差距：

| 场景 | CM−VGGT (N=50) | CM−VGGT (N=160) | 变化 |
|---|---|---|---|
| dl3dv-2 | +2.78 | +2.98 | ↑ |
| re10k-1 | +5.91 | +6.61 | ↑ |
| waymo | +9.59 | +10.11 | ↑ |

**再看位姿精度（ATE，占场景对角）：**

| 场景 | 初始化 | N=50 | N=160 | 变化 |
|---|---|---|---|---|
| dl3dv-2 | COLMAP | 0.472% | **0.073%** | **准 6.5 倍** |
| dl3dv-2 | VGGT | 0.222% | 0.246% | 基本不变 |
| dl3dv-2 | VGGT-Ω | 0.148% | 0.145% | 基本不变 |
| re10k-1 | COLMAP | 1.065% | **0.241%** | **准 4.4 倍** |
| re10k-1 | VGGT | 1.017% | 1.137% | 略差 |
| re10k-1 | VGGT-Ω | 0.220% | **0.214%** | 基本不变 |
| waymo | COLMAP | 1.036% | 1.022% | 不变 |
| waymo | VGGT | 1.311% | 1.351% | 略差 |
| waymo | VGGT-Ω | 1.195% | 1.243% | 略差 |

**这是本轮最重要的一张表：**

```
N=50  : COLMAP 位姿 0.472%  >  VGGT 0.222%     ← VGGT 更准
N=160 : COLMAP 位姿 0.073%  <  VGGT 0.246%     ← COLMAP 反超 3.4 倍
```

**COLMAP 的 SfM 需要足够多的视角才被良好约束**——50 帧时它的位姿是三者最差的，
160 帧时变成三者最好的。前馈方法（VGGT/Ω）的精度几乎不随帧数变化。

**所以"COLMAP 的优势随视角扩大"不是一个现象，而是两个叠加：**
1. 位姿精度从最差变成最好（0.472% → 0.073%）
2. 多视三角化点云在视角更多时质量提升更快

而 50 帧时 COLMAP **明明位姿更差、渲染却更好**，这正好佐证了
"瓶颈不在位姿而在点云"的结论（见 §4）。

### ② VGGT-Ω 从"最好"掉到"最末"（dl3dv）

```
dl3dv  N=50  : COLMAP 22.07 <  Ω 22.52      ← Ω 反超 COLMAP
dl3dv  N=160 : COLMAP 32.10 >  VGGT 29.12 >  Ω 28.38   ← Ω 垫底
```

**各方法从 50 → 160 帧的提升幅度：**

| 场景 | COLMAP | VGGT | VGGT-Ω |
|---|---|---|---|
| dl3dv-2 | **+10.03** | +9.84 | **+5.85** |
| re10k-1 | +1.67 | +0.97 | +1.21 |
| waymo | +1.40 | +0.88 | **+0.24** |

**Ω 从更多视角里获益最少**（dl3dv 少拿 4.2 dB，waymo 少拿 1.2 dB）。

推测原因：Ω 的导出点云同样是 `track length = 1.0`（逐帧深度反投影）。
帧数越多，这些**互不约束的点**之间的深度尺度漂移累积得越明显；
视角少时 3DGS 过拟合到极点，反而掩盖了这个缺陷。

> ⚠️ 这是推测，没有直接证据。要确认需要测量 Ω 导出点云的**多视一致性**
> （比如把 A 帧的点投到 B 帧看深度是否吻合）。已记为待办。

### ③ dl3dv 是对帧数最敏感的场景

```
dl3dv  50→160 帧：提升 10.0 dB
re10k  50→160 帧：提升 1.7 dB
waymo  50→160 帧：提升 1.4 dB
```

dl3dv 的 306 帧覆盖的相机位移远大于另外两个场景（包围盒对角 11.8 vs re10k 接近平面），
所以少给视角就直接少覆盖很大一部分场景。

## 4. 本次各步骤耗时（为什么花了 2 小时 35 分）

| 步骤 | 耗时 | 备注 |
|---|---|---|
| 环境搭建 + 缺依赖排错 | ~35 min | lightglue / hydra / pycolmap 3.10 分三次才发现 |
| LPIPS 的 VGG16 权重现场下载卡住 | ~20 min | 150 KB/s；开加速后 4 秒 |
| 数据上传 549 MB + 权重下载 9 GB | ~15 min | 并行 |
| **waymo COLMAP（185 帧 @1920×1280）** | **32.5 min** | 最大单项 |
| 其他 COLMAP | 6.7 min | dl3dv 2.2 + re10k 4.5 |
| VGGT 推理 3 次（199/195/185 帧） | 9.0 min | |
| **3DGS 训练 6 次（160 视角）** | ~55 min | 含一次被 CPU 争抢拖慢 6 倍的 |
| Ω 推理 + 训练 3 次 | ~45 min | waymo 那次 36 min（480×320 像素多、高斯多） |
| 3 个失败任务的手工补跑 | ~25 min | VGGT 缺依赖导致 |

### 三个真正的时间黑洞（已修进脚本）

**① CPU 争抢**
COLMAP mapper 占 8.6 个核 → 3DGS 训练从 90 it/s 掉到 14 it/s。
**已修**：`setup_linux.sh` 补全依赖，减少返工；调度上以后让 COLMAP 与训练串行。

**② waymo 的 SfM 在原生分辨率跑**
训练用 `-r 4`（480×320）但 SfM 阶段仍是 1920×1280。
**待改**：给 COLMAP 加 `--max-image-size 800`，预计快 3–4 倍。

**③ 缺依赖分三次发现**
**已修**（commit `aa84176`）：`setup_linux.sh` 现在一次装齐
`pycolmap==3.10.0`、`lightglue`、`hydra-core`、`omegaconf`、`onnxruntime`，
并**预下载 LPIPS 的 VGG16 权重**（528 MB）。

## 5. 本次未覆盖（诚实清单）

| 项 | 状态 | 影响 |
|---|---|---|
| **稠密设定的噪声重复** | ❌ n=1 | 没有标准差，稠密表的差距不能做统计检验 |

**报告里最需要补的是第一条**：稠密表的差距（2.98 / 6.61 / 10.11 dB）
虽然量级很大，但没有噪声门槛就不能写"显著"。

按 N=50 的实测噪声（dl3dv 0.38 / re10k 0.06 / waymo 0.22 dB），
这些差距都在 7–100 倍噪声以上，**大概率显著，但仍应实测**。
