# Part 1 剩余工作量与租卡预算

> 目的：在按小时计费的前提下，把 Part 1 还剩什么、每项要多久、总共要租多久算清楚。
> 所有耗时估算都基于我们**本机实测**的数据外推，不凭感觉。

## 一、Part 1 到底还差什么

原文对 Part 1 的要求是四个维度的对比：

> "Compare **initialization runtime**, **pose accuracy**, **3DGS convergence speed**, and **final rendering quality** across COLMAP, VGGT, and VGGT-Ω."

| 要求 | 现状 | 还差什么 |
|---|---|---|
| 初始化耗时 | ✅ 已有 COLMAP（98s / 216s / 838s） | VGGT、VGGT-Ω 的耗时 |
| **渲染质量** | ✅ COLMAP 三场景完整（33.41 / 34.34 / 35.29） | **VGGT、VGGT-Ω 各 3 场景** |
| **位姿精度** | ⚠️ 只有 COLMAP 的交叉验证（旋转 0.1° 级） | **三方 ATE 对比** |
| **收敛速度** | ⚠️ 只有 COLMAP 的曲线 | **三方收敛曲线** |
| Plan C（VGGT-Ω） | ❌ | 需核实是否开源；没开源就用 VGGT+BA 替代 |

**结论：Part 1 缺的全部集中在 Plan B / Plan C 上，而这正是 8 GB 显存跑不动的部分。**

## 二、三个必须先定的实验设计决策

### 决策 1：统一帧数 —— 必须做，否则对比不成立

VGGT 在 24 GB 上大概能吃 50–100 帧，而 COLMAP 我们用了 267 帧。
**如果直接比，就是把"初始化质量"和"帧数"两个变量混在一起。**

**方案：主实验统一用 N 帧（建议 N=50）跑三条路线。**

- COLMAP 也要在同样的 50 帧子集上重跑（快，1 分钟）
- 这样才真正隔离出"初始化方式"这一个变量
- 现有的 Plan A 全帧数结果**不浪费**，用作"帧数扩展"曲线的端点

### 决策 2：分辨率 —— 保持不变，不要升级

现有数据：`dl3dv-2`/`re10k-1` 是 256×256，`waymo` 是 480×320。

**建议保持不动。** 理由：
- 一旦改分辨率，**已有的 10 次 Plan A 实验全部作废**，得重跑
- 而且 256×256 下 3DGS 训练只要几分钟，租来的时间更值钱

★ 可选加一组"高分辨率验证"：`waymo` 用原生 1920×1280 跑三条路线，验证结论在更高分辨率下是否成立。**+1.5 h**，建议有余量再做。

### 决策 3：Plan C 用什么

先核实 **VGGT-Ω 是否放出代码和权重**（项目页 `vggt-omega.github.io`）。

- 有 → 直接跑，是最好的第三种配置
- 没有 → 用 **VGGT + bundle adjustment**（官方 `demo_colmap.py --use_ba`）替代。
  它仍然是一个有意义的第三配置（"前馈 + 几何后处理"），在报告里说明即可

## 三、实验矩阵与耗时

### 实测基准（本机 RTX 5070 Laptop，8 GB）

| 任务 | 实测耗时 |
|---|---|
| COLMAP 306 帧 256×256 | 98 s |
| COLMAP 279 帧 256×256 | 216 s |
| COLMAP 199 帧 1920×1280 | 838 s |
| 3DGS 30k，267 帧 256×256 | 9–18 min |
| 3DGS 30k，244 帧 256×256 | 11 min |
| 3DGS 30k，154 帧 480×320 | 17 min |
| 渲染 + 评测（39 视角） | 9 s |

**外推到 4090（24 GB）：3DGS 约快 3–4×，COLMAP 是 CPU 任务、大致相当。**
50 帧的 3DGS 训练预计 **2–3 分钟**。

### 阶段划分

| 阶段 | 内容 | 预计 | 说明 |
|---|---|---|---|
| **P0 环境** | Linux + CUDA + torch + 编译 3DGS 扩展 + 装 VGGT + 下权重 | **1.5–2 h** | Linux 上比 Windows 快得多，但权重 4.7 GB 要下 |
| **P1 摸底** | VGGT 显存/帧数扫描；VGGT-Ω 开源核实；定 N | **1.5–2 h** | 现在有 24 GB，可以真的扫到上限 |
| **P2 主实验** | 3 场景 × 3 初始化（统一 N=50） | **1.5 h** | 见下方拆解 |
| **P3 帧数扩展** | dl3dv-2 × N∈{20,50,100,200} × 3 初始化 | **1.5 h** | P1 报告里 "what scaling brings" 的核心 |
| **P4 噪声重复** | 关键组各 +2 个种子 | **0.75 h** | 没有它，0.5 dB 的差异不能当结论 |
| **P5 ATE + 图表** | 三方位姿精度 + 收敛曲线汇总 | **0.5 h** | |
| **P6 高分辨率（可选）** | waymo 原生 1920×1280 × 3 初始化 | **1.5 h** | 有余量再做 |
| **Buffer** | 报错、重装、重跑 | **30%** | 必须有 |

### P2 主实验拆解（每个场景）

```
COLMAP（50 帧子集）        1 min
VGGT 推理（50 帧）         2 min
VGGT-Ω / VGGT+BA 推理      2 min
3DGS 训练 × 3             3 × 3 min = 9 min
渲染 + 评测 × 3           3 × 1 min = 3 min
────────────────────────────────
单场景                     ~17 min
3 场景                     ~50 min   →  含 buffer 取 1.5 h
```

| 配置 | GPU 小时 |

| 不含可选阶段 | **7.5 + 30% buffer ≈ 10 h** |
| 含高分辨率验证 | **9 + 30% buffer ≈ 12 h** |

> **建议：租 12 小时（或按"一个完整工作日"计费）。**
>
> 按 4090 常见时租（⚠️ 具体价格以平台为准，我不掌握实时报价），
> 十几小时大概在**几十元量级**——真正的成本不是钱，是**你在线的有效时间**。

## 五、上线前必须做完的准备（不占 GPU，我现在就能做）

**租用时间最贵的浪费方式是"在机器上调试你自己的脚本"。** 所以：

| # | 准备项 | 状态 |
|---|---|---|
| 1 | 脚本路径可移植（不再硬编码 Windows 路径） | ✅ **已完成**（`COLMAP_BIN` 环境变量 + PATH 查找） |
| 2 | `env/setup_linux.sh`：一条命令装完 Linux 环境 | ⬜ 待写 |
| 3 | scripts/00b_fetch_vggt_weights.py：ModelScope → hf-mirror → 官方，三级回退 | ✅ 已完成 |
| 4 | scripts/00c_make_bundle.py：打包 images + splits + 已算好的 COLMAP 模型 | ✅ 已完成 |
| 5 | `scripts/run_p1_matrix.py`：一条命令跑完 P2+P3+P4 全矩阵 | ⬜ 待写 |

## 六、风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| VGGT-Ω 没开源 | Plan C 缺一角 | 用 VGGT+BA 替代，报告里说明 |
| VGGT 位姿约定不是"首帧为参考的 OpenCV 系" | 3DGS 训崩，浪费几小时 | **上线第一件事**：用现成的 `20_verify_poses.py` 验；它已经能自动判四种假设 |
| VGGT 导出的 COLMAP 格式有坑 | 3DGS 读不进去 | 官方 `demo_colmap.py` 直接吐标准格式，用它的 |
| 租的机器 CPU 很弱 | COLMAP 变慢 | 主实验 COLMAP 只用 50 帧，影响小 |
| 抢占式实例被收回 | 丢进度 | 每阶段结束立刻把 `results.csv` + 模型备份到本地/GitHub |
| 忘了监控显存 | 重演本机那次 | 保留 `run_with_guard.py`，24 GB 上设 20 GB 上限 |
