# Part 1 最终结果：COLMAP vs VGGT vs VGGT-Ω

> 环境：AutoDL / RTX 4090 24 GB / Ubuntu 22.04 / Python 3.12 / torch 2.8.0+cu128 / nvcc 12.8.93
> 评测口径：LPIPS = **vgg backbone，输入缩放到 [0,1]**（`net_type='vgg'`）
> 训练预算：**统一 50 个训练视角，30000 迭代**，其余参数全默认
> 数据：必做 3 场景 + 额外数据集 3 场景（Mip-NeRF 360）

---

## 0. 一页结论

| 维度 | 赢家 | 说明 |
|---|---|---|
| **渲染质量** | **COLMAP ≈ VGGT-Ω ≫ VGGT-1B** | Ω 在 dl3dv 上反超 COLMAP（+0.45 dB），另两场景落后 1.3 / 7.9 dB；VGGT-1B 全面落后 2.8–9.6 dB |
| **位姿精度** | **VGGT-Ω**（2/3 场景最准） | ATE 0.148% / 0.220% / 1.195%（占场景对角），COLMAP 0.472% / 1.065% / 1.036% |
| **初始化速度** | **前馈方法**（分辨率越高优势越大） | COLMAP 57 → 782 s 随分辨率暴涨（13.7×）；VGGT/Ω 恒定 70–100 s |
| **收敛速度** | 场景相关 | re10k/waymo 单调收敛；dl3dv 的 COLMAP 曲线**1k 就见顶后回落** |

**一句话**：VGGT-Ω 用 1/6 的时间拿到与 COLMAP 相当的渲染质量和更好的位姿；
VGGT-1B 的问题**不在位姿而在点云**（详见 §4）。

| m360-kitchen | 1559×1039 | 85 | **782 s** | — |
| m360-bonsai | 1559×1039 | 87 | **583 s** | — |

**关键规律：**

```
像素数 256² → 1558²（37 倍），COLMAP 耗时 57 s → 782 s（13.7 倍）
                       VGGT/Ω 始终 70–100 s（方差极小）
```

**分辨率越高，前馈方法的速度优势越明显。** 这是 Part 1 里最干净的定量结论。

```
特征提取   42.3 s

增量重建  455.0 s
```

## 3. 位姿精度（表 C）

| 场景 | 初始化 | 旋转误差（中位） | 相邻帧相对旋转 | ATE（占对角） |
|---|---|---|---|---|
| dl3dv-2 | COLMAP | 0.992° | 0.0971° | 0.472% |
| dl3dv-2 | VGGT | 0.216° | 0.0768° | 0.222% |
| dl3dv-2 | **VGGT-Ω** | 0.216° | **0.0592°** | **0.148%** |
| re10k-1 | COLMAP | **0.146°** | 0.0726° | 1.065% |
| re10k-1 | VGGT | 0.537° | 0.0599° | 1.017% |
| re10k-1 | **VGGT-Ω** | 0.173° | **0.0393°** | **0.220%** |
| waymo-405841 | **COLMAP** | 1.382° | **0.0399°** | **1.036%** |
| waymo-405841 | VGGT | 0.546° | 0.2069° | 1.311% |
| waymo-405841 | VGGT-Ω | 1.751° | 0.1025° | 1.195% |

**VGGT-Ω 在 dl3dv 和 re10k 上位姿最准**（ATE 0.148% / 0.220%），waymo 上略逊 COLMAP。

### 两个必须记住的评测陷阱

**① 旋转和 ATE 不能用同一个对齐**

re10k 的轨迹接近平面（对齐尺度仅 0.33），用相机中心做的 Umeyama 旋转绕平面法向欠定：
用它算旋转误差会得到 **1.53°**，而真实值是 **0.07°**（虚高 20 倍）。
所以旋转必须**单独用旋转平均**求全局对齐。脚本会打印「两种全局旋转的差异」作为诊断：
re10k 是 3.03°，dl3dv 只有 0.13° —— 一眼看出轨迹退化。

**② 相邻帧相对旋转误差是最可信的指标**

它与全局坐标系无关，不需要任何对齐，最适合判断"位姿对不对"。
上表里三者的相对旋转都在 0.04–0.21°，而全局 ATE 相差 7 倍 —— 说明**全局指标容易受退化影响**。

## 4. 核心发现：VGGT-1B 的问题在点云，不在位姿

用 COLMAP 的 `model_analyzer` 对比三种初始化的点云：

| 模型 | 点数 | **Mean track length** | 重投影误差 |
|---|---|---|---|
| COLMAP（dl3dv n50） | 3,778 | **8.19** | 0.544 px |
| VGGT-1B（dl3dv n50） | 100,000 | **1.000** | 0.000 px |
| VGGT-Ω（dl3dv n50） | 150,000 | **1.000** | 0.000 px |

**`track length = 1.000` 意味着每个三维点只出现在一张图里** ——
它们不是多视三角化的结果，而是**逐帧把深度图反投影**得到的点堆。
（重投影误差显示 0.000 px 是假象：每个点只在自己那一帧里，误差当然为零。）

这与位姿精度的结果正好互补：

```
位姿    ：VGGT-1B 0.222%  <  COLMAP 0.472%     ← VGGT 更准
渲染    ：VGGT-1B 19.26  <<  COLMAP 22.07      ← VGGT 更差
⇒ 瓶颈不在位姿，在点云
```

而 VGGT-Ω 用同样的"逐图反投影"点云，却能到 22.5 dB ——
原因是**它的深度和内参精度都更高**（内参误差 0.2–0.4%，见 §6），
所以反投影出来的点虽然不共享，但彼此位置一致。

**这是一个明确的后续方向**：如果用 VGGT 的位姿 + 三角化点云（而不是反投影点云），
渲染质量很可能追平甚至超过 COLMAP。

## 6. 方法论：这次踩到的坑（每个都会让结论错）

| # | 坑 | 症状 | 影响 |
|---|---|---|---|
| 1 | **COLMAP 单相机发散** | 相机中心飞到 7.2e9，包围盒对角 72 亿 | 3DGS 用它做尺度归一化 → 训练静默练废，**15.18 → 28.15 dB（+13）** |
| 2 | **VGGT-Ω 内参被多除了一次** | 导出 fx=0.4 而非 204 | 渲染等于从 500 倍远处看 → **9.11 → 22.52 dB（+13.4）** |
| 3 | **旋转/ATE 混用同一对齐** | re10k 旋转虚高 20 倍 | 会误判 VGGT 位姿很差 |
| 4 | **VGGT 输出不在 `sparse/0`** | `Could not recognize scene type!` | 3DGS 直接起不来 |
| 5 | **用数据集自带位姿就没耗时** | 额外数据集的 init 时间为 0 | 无法做速度对比 → 改成自己跑 SfM |
| 6 | **c2w / w2c 搞反** | waymo 旋转误差 23.5° vs 1.38° | 位姿指标完全失效 |
| 7 | **`extract()` 只拷贝存在的键** | `GroupParams has no attribute 'debug'` | 视频渲染起不来 |

> 坑 1 和坑 2 各自值 13 dB —— **都比我们想证明的结论（2–10 dB）更大**。
> 这说明：在稀疏视角任务里，**先把工具链的静默错误排除，比调实验更重要**。
